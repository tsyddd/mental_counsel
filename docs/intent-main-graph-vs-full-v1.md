# 意图识别主实验：图谱方法 vs 完整会话

用户明确的主对照是事件→意图图谱与完整对话模型，不是两路和三路检索阅读器。既有召回消融保留，但其 95.83% 等下游数字不能作为图谱主实验成绩。

沿用冻结 `data/recall_dataset_v1.json`，长/跨会话各 30 例，每例第 30 和 60 轮两个检查点，共 120 个检查点。每次会话至少 30 轮。不能把两种配对模式和两个节点当独立人物。

图谱分支逐轮回放双方消息，由当前部署的生产 Worker 每六轮抽取事件、维护意图；检查点直接导出 active 的 tentative/confirmed 意图节点及其真实支持事件。**不另外把 Top10 事件交给模型重新生成答案**。没有用户确认的节点仍标为候选，不自动称用户已同意。

完整历史基线每个检查点读取从首次会话至当前用户发言的全部双方消息，保留原文、角色、时间、会话 ID 和消息 ID；当前发言之后的助手回复和未来消息不进入基线输入。不摘要、不检索、不截断第一段会话，不给 gold、人工事件或目标数量。引用来源须为当前问题之前的用户消息。

两边请求基础模型相同，要求识别当前未解决的个人候选目标，保留主体、对象、期望改变和证据。图谱结构是现有生产实现：仍为两层，scene/activity 尚未接入生产写入和意图更新。**不能将当前实验写成三路情境图谱已实现或已验证**。

先冻结预测，再匿名化两组方法进行同一语义规则的一对一匹配；每组只能使用其引用证据，不借另一组补齐。评审可见 gold，预测不可见。记录 raw JSON，允许仅补一个缺失的最终根闭合符，不修改匹配文字和 ID。评审仍是同模型辅助，未独立人工审核。

报告意图级 micro precision/recall/F1、负例与来源有效性；记录全部失败和未评分节点，并报告所有预定参考意图分母下的保守 Recall。总调用次数和预算不同，不能宣称等成本。执行器并发 1，生产 Worker 保持单消费者，不启动并行消费者。

这是对比较口径的纠正。此前 v3 的 60 例最终点结果不能套用于本批；本批完成前不填写主实验准确率。生产回放需要处理约 600 个记忆批次，明显慢于只增加完整历史阅读器。

入口 `scripts/eval_graph_full_history_v1.py`，结果保存在 `checkpoints/graph-full-v1-*`。每次持久保存回放进度和检查点，以免中断后用后来的图谱冒充过去的状态。
