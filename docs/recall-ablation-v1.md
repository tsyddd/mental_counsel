# 三路召回与两路召回：节点级补漏诊断实验

本实验先冻结数据和规则，再运行。不以“三路必须胜出”作为样本筛选条件；包括退步和持平结果。数据集属于有意覆盖情境补漏的开发诊断集，不能据此声明自然分布上的普遍提升。

## 数据与评测节点

30 条人物组合轨迹，每条有长会话和跨会话两个配对版本，共 60 例。长会话 1×60 轮，跨会话 2×30 轮。每例第 30、60 轮为评测节点，共 120 节点。一轮为一次用户发言及一次脚本助手回复。每个节点只允许访问此前事件，不访问未来消息或标签。

每种模式 12 例双意图、12 例三意图、6 例纯负例。多意图样本也包含第三方、已经解决、满意、明确拒绝的干扰轨迹。节点发言重新提及历史问题，常通过对象、情境或后果指向以前的经历。查询由开发者依据轨迹编写，未独立人工审核；不是随机自然用户问题。

事件库使用此前用户原话切分的原子事件单元，保留消息时间、来源和会话。每个节点的查询消息不作为自己的历史证据，第 30 轮查询也不作为第 60 轮候选事件。日常与困难负例都保留在候选库，不仅放入 gold 事件。

这是有意固定事件单元、隔离召回效果的实验，不是生产事件抽取、去重或事件→意图图扩展的端到端实验。已经解决/第三方经历也可能是判断“没有当前意图”所需的相关历史证据：事件相关不等于意图为正。负例参考意图为空，参考证据为应读取的负例轨迹。

## 两组召回

- 两路沿用当前公式：`0.75 × E5余弦相似度 + 0.25 × 关键词词项Jaccard`。关键词实现是当前英文词/中文二元字符词项集合，不能写成 BM25。
- 三路：`0.8 × 两路分数 + 0.2 × 情境分数`。情境分数为 scene 和 activity 集合 Jaccard 的平均；其他/未知不构成匹配。
- scene/activity 只能从用户约定枚举中选择。事件与查询分别由同一模型独立标注，仅输入文本和枚举，不提供 gold、参考意图、事件轨迹 ID 或相关性。各条目不相互建立关联。
- 同一节点使用相同候选事件、同一 embedding、同一排序稳定规则、相同 Top-K。预先固定 K=3/5/10，不根据测试结果调权重。
- 另记“两路 Top10 并集情境 Top5”的候选补漏结果。由于候选数量可能增加，单独报告，不能拿它和固定 Top10 直接证明相同预算下更优。

## 意图识别对比

两组分别把各自 Top10 的完整事件交给相同意图识别模型，提示词、输出结构完全一致。场景标签只用于检索排序，不额外提供给三路阅读器。两组每次最多十个事件，但字符数/token可能不同，不宣称严格等 token 预算。

预测须保留主体、对象、期望改变和支持事件 ID，允许多个候选或无意图。先冻结两组预测，再将方法名称匿名化，由同一模型辅助判断语义和引用证据，按一对一匹配计算意图级 precision/recall/F1。评审可看到参考意图及源证据，预测模型看不到；这仍不是独立人工复核。部分槽位从少量经历即可推断，不能用结果证明所有目标必须多事件推理。

不在两组间共享预测答案，不给三路分支更多原始对话，不借已有参考意图或人工事件关联展开图。生产图扩展的收益需另做相同图结构下的下一阶段实验。

## 指标与报告

主报告：初始事件 Recall@3/5/10，辅以 Precision@n、nDCG@n；下游意图 micro precision/recall/F1、集合完全正确数。分别报告长会话、跨会话、正例节点及纯负例节点；失败与评审错误单列，不静默剔除。意图失败应在报告中给出保守分母分析，不能只报告成功节点。

区分第 30 与 60 轮，并统计三路独有命中、两路独有命中、额外无关事件。差异区间按人物 scenario_id 聚类 bootstrap，不能把配对模式和两个节点当独立人物。固定合成开发数据的区间不代表真实人群不确定性。

缓存保存标签与向量；记录实际模型名、每次调用输入和解析输出、时间及错误。本文不报告总 token 节省。所有任务串行、并发 1；不修改生产聊天、图谱或用户偏好。
