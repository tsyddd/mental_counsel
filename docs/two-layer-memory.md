# 当前实现：事件 → 意图

日期：2026-11-04。实现：`python/mindtrace.py`、`mindtrace_logic.py`、`mindtrace_preferences.py`、`go/mindtrace.go`。数据库仍为 PostgreSQL/pgvector，旧图谱不删除、不自动转换；新功能从新会话验证。

## 主流程

1. Go 校验登录和会话归属，将消息转发到内部 Python v2 接口。用户 ID 由认证信息派生。
2. 若有 queued/running 记忆任务，SSE 返回等待状态；若任务失败则返回错误，不拿旧窗口继续回答。默认等待上限 240 秒，超时前不保存新提问。
3. 取得用户级 PostgreSQL advisory lock，再次检查任务；保存用户消息，读取 user.md、最新完整窗口、最多一项待确认事项和最近 12 条双方消息。
4. 模型完成回复后保存回合，通过 SSE 返回文本和 done。当前 APIClient 是非 token 流式调用；SSE 提供等待、完成文本与错误，不宣称逐 token 生成。
5. 每第 6、12、18…个完整用户回合创建后台任务。`mt_jobs` 唯一键为 `(session_id,end_turn)`；SQL 是持久队列，Redis 只发送唤醒信号，因此丢失唤醒不会丢失任务。
6. Worker 取得同一用户级锁，抽取六轮事件和偏好，更新意图并发布固定窗口，最后标记完成。不同用户互不阻塞，同一用户串行；进程崩溃后 session advisory lock 自动释放，running 任务可以恢复领取。

## 事件去重与直接意图更新

抽取只信用户原话，助手提问/建议不是用户事实；源 ID 必须指向本批用户消息。事件保存摘要、主体、发生时间描述、原消息 ID、来源 session、原始回合范围和 384 维 E5 embedding。消息时间与事件时间不同，未知时间不编造。

按向量余弦与词项重合召回候选，再让模型判断是否为同一次经历。重复候选丢弃，不增加独立证据；不同时间或情境的相似经历分别保留，同批新事件也去重。

每个新事件分别召回局部历史事件，结合少量已有意图和本批对话，模型输出 create/update/link；证据不足返回空操作。`mt_intents` 保存描述、类别、状态及形成回合；`mt_intent_events` 保存支持/反向关系。没有概念层，不硬编码“三条事件就有意图”。

所有引用事件必须在该用户的候选集合内，新意图一律 tentative。新证据可以使旧意图 deferred/resolved；confirmed 与 rejected 不因普通支持证据自动变回 tentative。模型推断不等于用户同意。

当前面向个人演示规模：向量存放在 pgvector 列，Python 加载该用户事件做混合排序；不声称新链路已使用 HNSW 索引查询。

## 偏好、冲突与用户确认

偏好正文只保存到 `${USER_DATA_ROOT}/{UUID}/user.md`，最多 12 条、1,200 字符，每条 150 字符。规范化去重后，模型区分同义、冲突、新增；无冲突的明确持续偏好可以保存，推测或冲突先建立待确认项，不覆盖旧文件。临时许可不直接覆盖长期规则。

用户确认替换后删除旧偏好；拒绝候选或删除偏好记录到单独的停用文件，避免从旧对话恢复。文件锁、临时文件、原子替换保证一致更新。满额报出需要整理，不能静默截断偏好。

新意图也建立待确认项。聊天提示要求最多询问一项，偏好侧记提供确认/不接受按钮。按钮是当前确认的权威入口：接受意图才 confirmed，否认则 rejected；不根据沉默或模糊回复推断同意。确认后原子更新窗口中的意图状态；拒绝时移除对应意图条目，保留其他证据，不在六轮间额外检索。

## 固定上下文窗口与来源轮次

Worker 按最近六轮的各条用户发言检索事件，沿 `事件 → 意图 → 支持/反向事件` 展开，筛选为默认 2,400 字符以内的窗口。这是字符预算，不是 token 预算；偏好、待确认项和最近对话另占上下文。

```text
[事件 E1 | 会话 S1 第2-4轮 | 发生时间 上周] ……
[意图 I1 | 会话 S1 第6轮形成 | tentative] ……
```

窗口保存所选 ID、版本、来源会话和处理轮次，不截断半条记录；反向证据优先于普通支持候选。当前用户原话优先于旧窗口。聊天不每轮重新检索，若突然问到未覆盖的旧事，应说明依据不足。

## 会话结束、失败与重试

`POST /api/sessions/{id}/close` 整理不足六轮的尾批并生成阶段摘要；恰好整批结束也可执行仅巩固步骤。摘要存入 trace 供复核，固定记忆窗口仍以事件和意图为内容。关闭后新建会话继续。

失败保留任务错误，阻止继续用旧窗口回答；界面或 `POST /api/memory/jobs/{id}/retry` 重试。若插入事件后失败，重试重新利用该批已插入事件，不跳过意图更新。

## 接口、部署与边界

- Go：注册/登录、GET/PUT/DELETE `/api/auth/me`；会话、SSE 与作用域校验。
- GET `/api/memory`：两层图谱、固定窗口、任务与待确认项。
- GET `/api/preferences`、POST `/api/preferences/remove`：查看/删除偏好。
- POST `/api/confirmations/{id}`：显式接受或拒绝。
- 内部 `/v2/users/...` 不发布，Go 拒绝通用 `/api/v2/...` 代理绕过。
- 现有库先运行 `migrations/002_two_layer_memory.sql`；新库由 Compose 初始化。API 和 Worker 共享 USER_DATA_ROOT。

用户资料删除会清理该用户的消息、记忆、任务和偏好文件。旧视频服务及旧数据继续保留；旧三层接口的说明见根目录 MEMORY_DESIGN.md，不与新链路混算评测。
