# 多意图诊断集与下一轮对比方案

本轮仅构造数据及修订方案，尚未运行预测，也没有新成绩。此前 v3 冻结结果保留。

## 样本

每种模式 30 例：12 例含两个当前意图，12 例含三个当前意图，6 例无当前意图。每个多意图样本另加入一条第三方、已解决、正常满意或明确拒绝的干扰轨迹；纯负例混合两条负面判定轨迹。每种模式共 60 个目标意图，两种模式不能当成独立的 120 个目标。

长会话为 1×60 轮，跨会话为 2×30 轮，间隔七天；一轮是一问一答。不同意图的事件交错，每条轨迹前两条事件在前半程、后两条在后半程。每例同时有日常干扰消息。各例关键位置变化，避免固定位置泄露。

先定义事件轨迹及其目标，再展开为对话。评测标注包含主体、交互对象、期望改变、支持事件位置和最终状态；允许自然改写，不以唯一领域分类代替意图含义。父母与隐私边界、职业选择与家庭表达可以同时成立。一个意图有多个描述不应重复计分，两个不同目标也不应被宽泛描述自动算作都命中。

数据复用了开发过程中查看过的 v3 事件轨迹并重新组合，不是独立测试集；不能将它的成绩直接与 v3 相减宣布提升。仍需人工检查人物一致性、事件自然度、目标可推断性和负例状态；部分单事件足以形成候选意图，不能声称已证明多事件推理必需。

## 原完整历史基线究竟测什么

旧脚本 `scripts/eval_intent_v2.py::predict_baseline` 在最终回合，将全部 120 条双方消息按时间顺序交给同一请求模型 `gpt-6-sol`。每条含消息 ID、角色、内容、时间戳、会话 ID 及会话内轮次。跨会话没有截掉第一段会话，也没有先摘要。要求返回当前尚有证据的未解决候选意图及支持用户消息 ID，正常、第三方、已解决、拒绝不应误报。输入没有 gold、人工事件或分类定义。

图谱分支每六轮运行真实抽取、去重、意图维护任务，在最后读取尚活跃的意图节点；它不是从固定记忆窗口再次作答。两边基础模型相同，但调用次数和总 token 预算不同，也未固定 temperature/随机种子，所以不是同预算比较。当前实验只比较最终意图抽取，不评价回复质量、用户确认意愿或窗口召回效果。

旧评分器只看匿名意图描述，映射为互相重叠的类别，再要求类别集合完全一致。它不看证据，因此丢失对象的笼统意图和合理跨类别答案容易被混淆；旧“有无意图”指标不能评价多意图召回。

## 新评分方式（运行前仍需实现并审核）

1. 两个分支统一输出预测 ID、主体、交互对象、期望改变及来源用户消息 ID；不能给预测分支看 gold 或目标意图数量。
2. 将预测和参考意图匿名提交给独立人工评审，或以固定评审模型辅助后人工复核。评审可看必要源证据，分别核对目标含义、主体/对象和证据支持，不只匹配标签。记录评审依据与未决情况。
3. 对符合条件的预测—参考边做一对一最大匹配，每条预测和每条参考最多计一次。多目标混写先按固定规则拆分原预测，再匹配，避免一句泛化描述获得多次命中。
4. 主指标为意图级 micro/macro precision、recall、F1；另外报告每例集合完全正确率、纯负例误报率、混合样本干扰意图误报、重复意图率、对象缺失率和证据有效性。保留失败，不静默剔除。
5. 已解决和拒绝属于最终状态；如果以后加入中途检查点，必须独立标注当时状态，不能拿最终标签倒推中途答案。来源缺失可能是抽取遗漏或去重，需连到相应旧事件才能区分。

现有 v2/v3 单标签评分脚本不适用于 v4，不可直接套用或继续报告旧 100% 二分类成绩。

## 方法改进与可验证消融

- 意图写成结构化目标：主体、对象、问题、期望改变；显示用简短 label，推理保留完整槽位与证据，减少“表达情绪”替代“向父母表达受挫”的信息损失。
- 更新某个意图时强制带回其全部支持与反证，不只靠新事件相似度。不同意图分别检索，轮流分配候选额度，避免截取前若干条使一个主题挤掉另一个。
- 同义合并必须检查对象与期望改变，相关但不同的需求不硬合并。保留一事件支持多个意图的关系；用解决/拒绝证据更新状态，不能因为最近没有提到就删除。
- 分开评测图谱识别与对话记忆利用。当前窗口只取最多两个意图，多意图实验会触及这个限制；若后续改窗口，需要单独验证相关意图和证据覆盖率，不能把节点识别成绩当窗口覆盖率。
- 对中性日常事件降低推理优先级，不直接删除原证据；加入事件重要性和当前目标相关度，记录每次候选输入以定位遗漏发生在哪一步。
- 冻结“当前方法”和“改进方法”，在同一新数据、同一评审规则下与完整历史基线三方比较；再分别消融结构化意图、证据强制展开和主题均衡召回。执行并发保持 1。

原始模型响应、调用错误、token/耗时和输入证据都应保留。若比较成本，应计算图谱全流程累计调用，而非只计算最后一个窗口。多次运行按人物轨迹配对汇总，不能将两种模式或重复运行当独立病例。
