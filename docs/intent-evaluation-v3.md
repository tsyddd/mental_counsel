# 60 例长会话与跨会话诊断对比

## 运行前冻结的设计

一轮定义为一次用户发言及一次对应的助手回复。30 条不同的事件轨迹各自展开为两个版本：长会话 1×60 轮；跨会话 2×30 轮，间隔七天。每种模式有 30 例、1,800 轮；总共 60 例、3,600 轮、7,200 条消息。两种版本配对，统计时不能视为 60 个独立人物。

每种模式有 18 个正例、12 个负例。正例为学习负担、同伴参与、家庭沟通、睡眠作息、工作边界、私人关系边界六类，各三条轨迹；负例为第三方经历四条、已经解决四条、正常状态两条、明确拒绝两条。

先编写四个有时序的关键事件与最终参考意图，再分散到第 4、22、39、57 个全局回合，其余回合为日常干扰内容。跨会话版本前两个事件在第一次会话，后两个事件在第二次会话。助手回复预先编写，不注入参考意图。相同轨迹两种模式的用户发言完全一致，仅改变会话边界和时间。

数据由开发过程中编写，未经过独立人工或心理专业复核。部分单条事件可能已足以提出候选意图，不能声称这套数据已经证明多事件推理不可替代。填充内容从固定日常话题池产生，后续需要更自然的独立人物长对话验证。

## 两个实验分支

- 图谱：实际 PostgreSQL/pgvector、生产抽取和意图维护函数，每六轮提交 Worker，读取最终尚有效的 tentative/confirmed 意图节点。
- 完整历史：同一基础模型，一次接收全部带时间戳、会话标识与消息 ID 的双方对话，直接输出当前尚未解决的候选意图。

两边预测输入都不包含 gold、类别定义或人工事件列表。只在最终检查点计分；已解决、明确拒绝、第三方经历不是当前个人意图。候选识别与用户确认是否接受是两个不同步骤，不能将候选节点说成用户已确认目标。

分别报告每种模式的意图有无判断 accuracy、precision、recall、F1 及混淆矩阵。类别语义用同一类别表进行匿名预测描述映射，单独报告，不能将其当成人工评审。公开原始预测、错误、来源证据和窗口，失败不能静默剔除。当前不测端到端聊天质量、临床疗效或总体 token 成本。

## 冻结与复现

数据：`data/intent_dataset_v3.json`；SHA-256：`61d1d8a98cb2e23c44bc8bb69b5d547657c48ea28686dc8526a2cb73365ca8b5`。

构造：`python scripts/build_intent_dataset_v3.py`。运行：`scripts/eval_intent_v2.py --dataset ... --output ... --limit 60 --workers 8`。临时多消费者只并行不同用户的生产 Worker 函数，不修改提示词、模型或每用户串行锁。两组预测请求模型标识相同，实际标识写入结果文件。

运行策略更新：根据用户要求，已关闭临时并行消费者；既有已提交批次由唯一生产 Worker 顺序收尾，剩余样本以 `--workers 1 --resume` 运行，后续类别映射也为并发 1。保留此前已完成的预测，不重新挑选结果；中断样本的已有批次记录仍保留，不计为新的独立样本。

这次扩大后的实验独立保存为 v3，不覆盖此前 8 例小诊断集与结果。结果尚未完成时不得沿用此前 8/8 填写本批指标。
